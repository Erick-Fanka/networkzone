## 1.1.1 Sequência de inicialização do Switch

Este tópico explica a sequência de inicialização do switch, pois antes mesmo de começarmos a configuração o switch passa por 5 etapas de inicialização:

- **Etapa 1:** Primeiro, o switch carrega um programa POST (Power-on Self-Test) onde é armazenado na ROM. O POST verifica o subsistema da CPU, testa a CPU, DRAM e a parte de flash que compõe o sistema de arquivos flash.
- **Etapa 2:** Depois, o switch carrega o software carregador de inicialização. O carregador de inicialização (boot loader) é um programa pequeno armazenado na ROM que é executado imediatamente após a conclusão bem-sucedida do POST.
- **Etapa 3:** O carregador de inicialização executa inicialização de baixo nível da CPU. Ele inicializa os registros da CPU, que controlam onde a memória física é mapeada, a quantidade de memória e sua velocidade.
- **Etapa 4:** O carregador de inicialização (boot loader) inicializa o sistema de arquivos da memória flash na placa do sistema.
- **Etapa 5:** Finalmente, o carregador de inicialização localiza e carrega uma imagem do software de sistema operacional IOS padrão na memória e passa o controle do switch para o IOS.

## 1.1.2 O comando boot system

Nesta etapa temos o nosso comando BOOT o que seria isso? Quando o switch tenta inicializar ele procura uma variável chamada BOOT porque nessa variável temos o PATH "caminho" do nosso arquivo `.bin`, este arquivo bin é onde temos a ISO do nosso sistema operacional, em switches cisco chamamos de IOS. Caso a variável não foi configurada ou não tem por algum motivo, o switch entra em um modo de "sobrevivência" porque ele começa a buscar na memória o primeiro arquivo executável.

Aqui temos um exemplo da variável de ambiente BOOT, ela é definida usando o comando de modo de configuração `boot system`:

- `boot system` = o comando principal
- `flash` = o dispositivo de armazenamento
- `c2960-lanbasek9-mz.150-2.SE/` = o caminho para o sistema de arquivos
- `c2960-lanbasek9-mz.150-2.SE.bin` = o nome do arquivo IOS

## 1.1.3 Alternar indicadores LED

Aqui temos a explicação dos indicadores de led dos switches catalyst. Podemos usar os LEDs do switch para monitorar rapidamente o desempenho e atividade do switch. Os switches de diferentes modelos e recursos terão LEDs diferentes e sua colocação no painel frontal pode variar.

Segue logo abaixo a explicação de cada finalidade dos indicadores LED:

1. **SYST - LED de Sistema:** Mostra se o sistema está recebendo energia e está funcionando corretamente. Se o LED estiver desligado significa que o sistema está desligado. Se o LED estiver verde, o sistema está funcionando normalmente. Se o LED estiver âmbar, o sistema está recebendo energia mas não está funcionando corretamente.

2. **RPS - LED do sistema redundante de fonte:** Mostra o status do RPS. Se o LED estiver apagado, o RPS está desativado ou não foi conectado corretamente. Se o LED estiver verde, o RPS está conectado e pronto para fornecer energia reserva. Se o LED estiver piscando em verde, o RPS está conectado mas não está disponível porque está fornecendo energia para outro dispositivo. Se o LED estiver amarelo, o RPS está no modo de espera ou em uma condição de falha. Se o LED estiver piscando na cor âmbar, a fonte de alimentação interna do comutador falhou e o RPS está fornecendo energia.

3. **Status da porta:** Indica que o modo de status da porta está selecionado quando o LED está verde. Este é o modo padrão. Quando selecionado, os LEDs de porta exibirão cores com significados diferentes. Se o LED estiver apagado, não há link ou a porta foi desligada administrativamente. Se o LED estiver verde, um link está presente. Se o LED estiver piscando em verde, há atividade e a porta está enviando ou recebendo dados. Se o LED estiver alternando verde-âmbar, há uma falha de link. Se o LED estiver amarelo, a porta está bloqueada para garantir que não exista nenhum loop no domínio de encaminhamento e que este não esteja enviando dados (normalmente, as portas permanecerão nesse estado por aproximadamente 30 segundos após serem ativadas). Se o LED estiver piscando em âmbar, a porta será bloqueada para evitar um possível loop no domínio de encaminhamento.

4. **DUPLX - LED da porta duplex:** Indica que o modo duplex da porta está selecionado.

5. **SPEED:** Indica que o modo de velocidade da porta está selecionado. Quando selecionado, os LEDs de porta exibirão cores com significados diferentes. Se o LED estiver apagado, a porta está operando a 10 Mbps. Se o LED estiver verde, a porta está operando a 100 Mbps. Se o LED estiver piscando em verde, a porta está operando a 1000 Mbps.

6. **PoE - LED do modo Power over Ethernet:** Se PoE for suportado, um LED de modo PoE estará presente. Se o LED estiver desligado, indica que o modo PoE não está selecionado e que nenhuma das portas foi negada energia ou colocada em uma condição de falha. Se o LED estiver piscando em âmbar, o modo PoE não está selecionado, mas pelo menos uma das portas foi negada energia ou tem uma falha PoE. Se o LED estiver verde, ele indica que o modo PoE está selecionado e os LEDs da porta exibirão cores com significados diferentes. Se o LED da porta estiver desligado, o PoE está desligado. Se o LED da porta estiver verde, o PoE estará ligado. Se o LED da porta estiver alternando verde âmbar, PoE será negado porque o fornecimento de energia ao dispositivo alimentado excederá a capacidade de alimentação do switch. Se o LED estiver piscando âmbar, PoE está desligado devido a uma falha. Se o LED estiver âmbar, o PoE para a porta foi desativado.

## 1.1.4 Recuperando de um travamento de sistema

Neste capítulo vamos aprender como recuperar após um travamento de sistema. O carregador de inicialização fornece acesso ao switch se o sistema operacional não puder ser usado devido a arquivos ausentes ou danificados. O carregador tem uma linha de comando que fornece acesso aos arquivos da memória flash.

Podemos acessar ele usando um cabo console com os seguintes passos:

- **Etapa 1:** Conecte um PC pelo cabo do console à porta do console do Switch. Configure o software de emulação de terminal para conectar-se ao comutador.
- **Etapa 2:** Desconecte o cabo de alimentação do Switch.
- **Etapa 3:** Reconecte o cabo de alimentação, e dentro de 15 segundos, pressione e mantenha pressionado o botão MODE enquanto o LED do sistema ainda estiver piscando verde.
- **Etapa 4:** Continue pressionando o botão MODE até que o LED do sistema fique brevemente âmbar e verde sólido; em seguida, solte o botão MODE.
- **Etapa 5:** The boot loader `switch:` aparece no software de emulação de terminal no PC.

Digite `HELP` ou `?` no prompt para que assim ele exiba uma lista de comandos disponíveis.

Por padrão, o Switch tenta inicializar automaticamente com aquela variável que falamos lá no início "BOOT", então para conseguirmos ver o caminho que a variável usa rodamos o comando `SET`, assim mostrando o caminho do nosso arquivo `.bin`, logo após rodamos o comando `flash_init` para inicializar o switch.

**Exemplo:**
witch: set
BOOT=flash:/c2960-lanbasek9-mz.122-55.SE7/c2960-lanbasek9-mz.122-55.SE7.bin
(output omitted)

switch: flash_init
Initializing Flash...
flashfs[0]: 2 files, 1 directories
flashfs[0]: 0 orphaned files, 0 orphaned directories
flashfs[0]: Total bytes: 32514048
flashfs[0]: Bytes used: 11838464
flashfs[0]: Bytes available: 20675584
flashfs[0]: flashfs fsck took 10 seconds.
...done Initializing Flash.

Após a inicialização vamos rodar o comando `dir flash:` para visualizar os diretórios e arquivos em flash.

**Exemplo:**
switch: dir flash:
Directory of flash:/

Logo após temos o comando `BOOT=flash` para alterar o caminho da variável BOOT. Para verificar o novo caminho da variável é só digitarmos o comando `SET` novamente.

**Exemplo:**
switch: BOOT=flash:c2960-lanbasek9-mz.150-2.SE8.bin
switch: set
BOOT=flash:c2960-lanbasek9-mz.150-2.SE8.bin
(output omitted)

switch: boot

Por fim os comandos do carregador de inicialização suportam inicialização do flash, formatação do flash, instalação de um novo IOS, alteração da variável de ambiente BOOT e recuperação de senhas perdidas ou esquecidas.

## 1.1.5 Acesso ao gerenciamento de switches

Para preparar um switch para acesso de gerenciamento remoto, o switch deve ser configurado com um endereço IP e uma máscara de sub-rede. Lembre-se de que, para gerenciar um switch a partir de uma rede remota, o switch deve ser configurado com um gateway padrão.

Isso é muito semelhante à configuração das informações de endereço IP em dispositivos host.

## 1.1.6 Exemplo de configuração do SVI do Switch

SVI (Switch Virtual Interface), o próprio nome já diz o que ele é: uma interface virtual. Ele fica responsável pelo inter-vlan em switches L3, gerenciamento remoto e default gateway.

Por padrão o switch está configurado para ter seu gerenciamento controlado pela VLAN 1. Todas as portas são atribuídas a ela por default.

Por motivos de segurança, é uma prática recomendada usar uma VLAN diferente da VLAN 1 para a VLAN de gerenciamento, como a VLAN 99 por exemplo.

**Passo 1: Configurar a interface de gerenciamento**
Entre no modo de configuração global = # configure terminal
Entre no modo de configuração da interface para SVI = # interface vlan 99
Configure o endereço IPv4 = # ip address 172.12.99.11 255.255.255.0
Configurar o endereço IPv6 = # ipv6 address 2001:db8:acad:99::1/64
Ative a interface de gerenciamento = # no shutdown
Volte para o modo EXEC privilegiado = # end
Salve a configuração atual = # copy running-config startup-config

**Passo 2: Configurar o gateway padrão**
Entre no modo de configuração = # configure terminal
Configure o gateway padrão do switch = # ip default-gateway 172.17.99.1
Volte para o modo EXEC privilegiado = # end
Salvar a configuração = # copy running-config startup-config

**Passo 3: Verificar Configuração**
Comando para verificar: # show ip interface brief
